Port status

Read from the three repositories themselves — the engine, the Entity Framework Core provider and the linq2db provider. The project's own wording: a feature missing from the port is unfinished work, not a property of the database; the orientation is the frozen documentation and the reference jar, not the port's current state.

Status in one line: a usable subset runs end to end — an ADO.NET provider over an engine that reads in-memory and file databases: open connection, DDL, DML, query, reader, Dapper — and both provider projects run alongside it, their green gates grown many times over since the last update.

The roadmap's own legend counts a fourth state beside done, partial and todo: refuses — the class is there, it parses, and then it throws TODOException rather than answering. The port is broad but shallow, and a stub that refuses is never a stub that answers.

Not yet — as port defects, not as limits of H2

Each of these exists in H2 2.5 and will be in the port. The providers' own registries name them, say whose work they are, and keep the failing tests in the suite, tagged BlockedByPort, so the port's remaining work stays visible instead of quietly disappearing.

  • Rights and privileges — CREATE USER/ROLE, GRANT, SET PASSWORD/SET SALT: the classes are the phase-7 work and still refuse.
  • Java CREATE ALIAS and calling one — the last TestScript blocker; the port cannot load Java classes, and substituting a .NET method would be a separate ADR decision, not a port.
  • DDL families still to port: triggers, materialized views, linked tables, constants, RUNSCRIPT/BACKUP, EXECUTE IMMEDIATE.
  • Reading a CHARACTER LARGE OBJECT back out of a table row: the storage is there and memory lobs read fine, but a lob tied to a table refuses in ValueLob.CopyToResult.
  • ALTER TABLE tails — DROP COLUMN and RENAME forms — and COMMENT ON beyond the basics.
  • DB_CLOSE_DELAY: an in-memory database is dropped when its last connection closes, so a pooled data context cannot put it down and pick it up later.
  • File databases: CIPHER encryption and the INIT runscript refuse; the plain open, the format and the locking are in.
  • One catalogue divergence: the collation column is empty where H2 2.5 gives the collation of the database.
  • A second transaction on one connection — the ADO layer refuses it; the EF Core transaction family waits.

The providers

Two provider projects run alongside the engine, each in its own repository, each with its own history: dimzon/h2sharp-efcore — a fork of EFCore.PG with PostgreSQL's surface replaced by H2's, keeping EF Core's own specification suite as the measure; and dimzon/h2sharp-linq2db — written from scratch against linq2db's public API, not a fork. Both were last re-measured on 2026-10-27 against engine 85b425e, on net9.0 and net10.0; the engine has since moved to 5406aa7 without a provider release.
