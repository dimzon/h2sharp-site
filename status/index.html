Port status

Read from the three repositories themselves — the engine, the Entity Framework Core provider and the linq2db provider. The project's own wording: a feature missing from the port is unfinished work, not a property of the database; the orientation is the frozen documentation and the reference jar, not the port's current state.

Status in one line: a usable subset runs end to end — an ADO.NET provider over an in-memory engine: open connection, DDL, DML, query, reader, Dapper — and two provider projects run alongside it.

Landed since the last update

FeatureWhat landed
JOINTwo tables are read as one — the reference's own readTablePrimary/readTableReference loop with INNER, JOIN, LEFT/RIGHT [OUTER], CROSS and NATURAL, plus ON/USING. This was the largest blocker for the providers: without it an EF Core query with navigation does not read.
AS in aliasesBoth the table alias and the column alias, with and without AS — the grammar allows either.
FINAL TABLEThe rows an insert changed are read back through it — this is how a generated key comes back, the reference having no INSERT … RETURNING.
SequencesCREATE SEQUENCE … START WITH n, NEXT VALUE FOR, CURRENT VALUE FOR.
Identity and generated columnsGENERATED BY DEFAULT AS IDENTITY and generated columns, with the value read back.
Catalogues and schemasThe catalogue is filled completely, LOBs are stored in the row, the schema is created and tables may name it, the database can be emptied and the catalogue names the database.
Query shapesCommon table expressions and the values table are read as tables, a derived table is read from a query, the sign in front of a term negates it, parameters are no longer limited to eight, and a LIMIT count is read as an expression.
Current date and timeCURRENT_DATE, CURRENT_TIME, CURRENT_TIMESTAMP with an optional scale, and CURDATE/CURTIME/NOW as compatibility spellings. The tests hold the clock, the random numbers and the UUIDs, so the values are exact.

Not yet — as port defects, not as limits of H2

Each of these exists in H2 2.5 and will be in the port. The providers' own registries name them, say whose work they are, and keep the failing tests in the suite, tagged BlockedByPort, so the port's remaining work stays visible instead of quietly disappearing.

  • MERGE — the last red test in the ADO.NET suite.
  • Window functions (OVER/FILTER). Note that Entity Framework Core 9 does not translate them into a query at all, so there is nothing for the provider to write; and a derived table around the range table is not read yet.
  • File databases. The store itself is in the port and its format is H2 2.5-compatible — MvStoreFileCompatTests checks that — but a session does not open a file database yet, and a pooled connection takes an in-memory database with it.
  • CREATE SCHEMA — which is what the scaffolding still needs: it makes a schema of its own before asking about the tables in it.
  • Two things in the catalogue that are not what H2 2.5 has: the catalogue is named by the path of the database in the URL where H2 names it by the database name, and the collation of a column is empty where H2 gives the collation of the database.
  • Reading a CHARACTER LARGE OBJECT back out of a row: the storage is there, the way out into a result is not.
  • IN with a subquery, and the query layer's resolver for some quoted forms.
  • Constraints and rights (phase 7).

The providers

Two provider projects run alongside the engine, each in its own repository, each with its own history: dimzon/h2sharp-efcore — a fork of EFCore.PG with PostgreSQL's surface replaced by H2's, keeping EF Core's own specification suite as the measure; and dimzon/h2sharp-linq2db — written from scratch against linq2db's public API, not a fork.
