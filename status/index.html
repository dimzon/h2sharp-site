Port status

From the project's own docs/ROADMAP.md ↗ and README. The roadmap's Current status block is pinned to the commit it was written at, and new work lands after it — so this page quotes it, then adds what has landed since.

Status in one line: a usable subset runs end to end — an ADO.NET provider over an in-memory engine: open connection, DDL, DML, query, reader, Dapper.

Newer than the roadmap block

Verified in the source, not taken on trust from commit titles:

Landed after the roadmap refreshWhat it means
Predicates: BETWEEN, IN (list and constant set), LIKE, ILIKE, REGEXP, NOTPorted as the reference's own predicate types — BetweenPredicate, ConditionIn / ConditionInList / ConditionInConstantSet, CompareLike, ConditionNot — not a shortcut in the parser, and none of them refuses.
CASE, both formsSimpleCase and SearchedCase with OperationN.
Aggregates: JSON_ARRAYAGG, JSON_OBJECTAGG, HISTOGRAM, MODEJSON aggregates build straight into bytes; HISTOGRAM/MODE on a value-to-count map.
Window frame units, bound types, exclusionsThe frame machinery is ported. Window functions (OVER/FILTER) still are not.
UPDATE SET listBuilt from the reference's update-action array.
Built-in functionsA function dispatcher plus the built-ins: ABS, MOD, FLOOR/CEIL/ROUND/TRUNC, the trigonometry, LN/EXP/SQRT/LOG/POWER, the whole bit family (BITAND…ROTATERIGHT), EXTRACT, DATE_TRUNC, DATEADD/DATEDIFF, FORMATDATETIME/PARSEDATETIME, DAYNAME/MONTHNAME, the string family (UPPER…SUBSTRING, TRIM, LPAD/RPAD, REPLACE, REGEXP_*, SOUNDEX/DIFFERENCE), XML*, JSON_OBJECT/JSON_ARRAY, array functions, COMPRESS/EXPAND, CONCAT, COALESCE, NULLIF, RANDOM.
AS in a table aliasParsed and pinned against the reference's answers. The implicit alias (FROM T e) worked before; note that bare column aliases still refuse.
Statements commit at the reference's pointsThe reference's stop and commitIfNonTransactional are ported, so a single INSERT/UPDATE/DELETE is durable on its own and DDL commits its transaction.
CREATE TABLE … PRIMARY KEYCreates, names and drops the index the way H2 does — the PRIMARY_KEY_ prefix, and the same name back when the table is recreated, as on the JVM.
Constraints are schema objectsNamed and table-level PRIMARY KEYs own their index and the 23505 duplicate-key prefix; ALTER TABLE adds and drops them and frees their names.
CREATE INDEX / DROP INDEXPorted over the full MVSecondaryIndex and its row factories.
LIKE / REGEXP semanticsSemantics suites pass; the default LIKE escape and IN parameter binding were fixed.
Allocation workPooled page scratches, one Bits.Reverse for the MVStore byte helpers, the pattern Regex cached once, digit appends without an intermediate string, numeric conversion delegates hoisted to statics.
Differential harnessOracle snippets compile once into a per-machine cache and run from it, so the JVM side costs nothing per repeat.

SQL conformance suite

The repo now carries tests/H2SharpSql.Specs — 947 tests, one per documented SQL construct, each anchored to a line number in the frozen snapshot the repo keeps in docs/. It is deliberately not part of H2Sharp.sln: while the port is young it shows hundreds of failures, and the daily ritual dotnet test H2Sharp.sln should not depend on it.

The biggest gaps by failure count: EXTRACT in the parser (66), FILTER/OVER (35), INFORMATION_SCHEMA as a table (25), CREATE DOMAIN (15), ALTER TABLE beyond ADD/DROP CONSTRAINT (12), YEAR (12), derived tables (12), CREATE ROLE (11), HOUR (10), table constraints other than PRIMARY KEY (9), CREATE SEQUENCE (8).

Why the numbers differ from the site's mirror: the frozen docs are H2 2.5.252, while the reference checkout the port is written against is 2.5.259-SNAPSHOT (reference/H2_COMMIT.txt). On a disagreement the reference wins, not the snapshot. This site's mirror is the same 8 files the repo commits, verified byte-for-byte — python tools/verify-snapshot.py.

The EF Core provider

It lives in its own repository, dimzon/h2sharp-efcore private — a fork of EFCore.PG with PostgreSQL's surface replaced by H2's, keeping EF Core's own specification suite as the measure. 1052 of 1227 inherited tests pass against the pinned reference engine.

The provider does not bend to the engine's gaps — it generates what H2 2.5 requires and records the divergence. The engine gaps it is waiting on are numbered in its docs/DIVERGENCES.md: quoted column references, AS aliases (now landed), GENERATED … AS IDENTITY, FOREIGN KEY in CREATE TABLE, INTERVAL types, DB_CLOSE_DELAY, the INFORMATION_SCHEMA catalogue, and CREATE SEQUENCE.

Not yet

So the SQL mirror is not a promise about what runs — it documents H2's full grammar, while the engine executes the subset above:

  • JOIN, subqueries, window functions (OVER/FILTER), MERGE, MERGE USING, EXPLAIN — the window frame machinery is ported, window functions are not
  • The SAVEPOINT statement — row operations use an internal savepoint, which is not the SQL command
  • The reference's statement scope, savepoint wrapping and rollback of a failed attempt — the comments in Command.cs say so outright; ExecuteQuery and batch execution still refuse
  • Sequences in DDL; the INFORMATION_SCHEMA catalogue
  • File databases and async OpenAsync — in-memory only today
  • Constraints and rights, EF Core
  • Table constraints other than PRIMARY KEY; CREATE SEQUENCE, CREATE DOMAIN, CREATE ROLE
  • INFORMATION_SCHEMA as a queryable table — 0 of 37 system-table tests pass
  • Quoted column references (SELECT "e"."Id") — the query layer's resolver is not ported
