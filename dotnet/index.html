Three projects, three version lines

A provider is chosen by the thing it is built into, so its number is that thing's line:

ProjectLineWhat the number means
H2Sharp — the engineits own, 0.x while the port is unfinishedhow far the port is written
H2Sharp.EntityFrameworkCorethe EF Core line, M.mwhich EF Core version the provider works with
H2Sharp.Linq2Dbthe linq2db line, M.mwhich linq2db version the provider works with

A program on EF Core 9.0 takes the 9.0-line provider and no other: another major EF Core is a different world of configuration and APIs. The engine has nothing it is built into, so it has its own line — the H2 version it reproduces (2.5) is written in the package description and the README, but not in the number, because the port is not H2 2.5 and a number saying "2.5" would claim exactly that.

The state of the work rides in the suffix: 9.0.5-alpha.1 is the first build after the fork, 9.0.6-alpha.1 is our next fix on the same EF Core line, and 0.1.0-alpha.1 is the engine in progress. The patch counts our changes, not the upstream's — a provider tracking EF Core 9.0.5 is not EFCore.PG 9.0.5, and the number must not say it is.
